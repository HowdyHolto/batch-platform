mother — Detail Card System
mother · artifact system · proposal 01

One skeleton,
many organs.

Every artifact mother ingests gets a detail card built from the same eight zones in the same order — only the modules inside them change by file family. Below: the zone map, then eleven fully-worked cards across two waves. Zone tags (Z1–Z8) stay visible on every card so the shared anatomy is legible.

Z1
Hero
The content itself, interactive. Waveform, player, zoomable image, schema grid.
Z2
Identity
Type badge, editable title, AI caption, provenance & boost state.
Z3
Facts
4–6 type-specific stats. Tap a fact to filter the library by it.
Z4
Actions
One primary verb per family (always spacebar) + universal verbs.
Z5
Intelligence
Machine-extracted content in a fixed tab vocabulary. Suggestions carry receipts.
Z6
Context
Tags (human vs auto, visibly distinct), project, freeform notes.
Z7
Connections
Related artifacts, people, timeline neighbors — fed by the brain.
Z8
Record
Activity, versions, the exhaustive metadata table, storage.

What keeps sixteen families feeling like one product

R1
Zones never reorder. A module may be absent; its zone collapses. Nothing moves.
R2
One primary verb per family — Listen, Play, View, Query, Read — always first, always on spacebar.
R3
Facts are always the stat-block idiom: big light value, small tracked label. Four to six, never more.
R4
Intelligence tabs come from a fixed vocabulary — Transcript, Summary, Text, Items, Entities, Schema, Dependencies.
R5
Machine voice is always legible: ✦ marks AI captions, dotted chips mark auto-tags. Confirming promotes them.
R6
Every suggestion shows its receipt — the timestamp, page, or cell it came from — and nothing leaves without an accept.
R7
Same kit everywhere: block, stat, chip, tag, list row, tab bar, player shell. A new family is a composition, not new components.
R8
Unknown formats still get the full universal layer — provenance, tags, notes, prompt, share. Never a dead end.
